# 基於 TensorFlow Object Detection API 之水果影像辨識系統操作手冊

## 組員:11325034 許竣傑  11325036 蔡典佑

## 一、研究目的

本專案以 TensorFlow Object Detection API 為基礎，建立水果影像辨識系統。透過蒐集水果圖片、建立影像標註資料、轉換訓練資料格式及訓練物件辨識模型，使模型能夠學習水果的外觀特徵，作為後續影像辨識的基礎。

本操作手冊將依照實際操作流程，介紹環境準備、圖片蒐集、影像標註、資料格式轉換、模型訓練、模型匯出及錯誤排除等步驟。

## 二、環境準備與程式架構

### 2.1 安裝及確認 Python 環境

首先確認電腦或雲端執行環境已安裝 Python 3，並確認相關套件能夠正常執行。Python 是本專案使用的程式語言，TensorFlow 則負責模型訓練與物件辨識相關工作。

### 2.2 準備 TensorFlow Object Detection API

本專案使用 TensorFlow Object Detection API 處理物件辨識相關工作。在執行程式前，必須確認相關套件已正確安裝，並確認程式可以找到所需的模組。

### 2.3 確認專案資料夾

本專案使用圖片資料、標註資料、訓練資料及模型輸出資料夾，相關路徑應依照實際專案設定確認。

主要資料包含：

- `images/train`：訓練用圖片。
- `images/test`：測試用圖片。
- `images/train_labels.csv`：訓練資料的標註資訊。
- `images/test_labels.csv`：測試資料的標註資訊。
- `data/train.record`：轉換後的訓練資料。
- `data/test.record`：轉換後的測試資料。

以上檔案名稱與路徑應依照實際程式內容確認，避免因資料夾位置或檔案名稱不一致而造成執行錯誤。


## 三、蒐集水果圖片

### 3.1 安裝 Download All Images 擴充程式

首先開啟 Google Chrome 瀏覽器，搜尋並安裝名為 **Download All Images** 的擴充程式。此工具可以擷取目前網頁中的圖片，並將圖片下載成 ZIP 壓縮檔，以便後續整理訓練資料。

安裝完成後，可前往 Google 圖片搜尋需要辨識的水果，例如 Apple（蘋果），再使用擴充程式下載所需圖片。

## 四、使用 LabelImg 進行影像標註

### 4.1 安裝及開啟 LabelImg

圖片整理完成後，需要使用 LabelImg 進行影像標註。首先依照電腦環境準備 Python 及相關套件，再透過命令提示字元或終端機安裝、啟動 LabelImg。

若原始操作流程是透過 Windows 控制台進行設定，可依實際畫面記錄操作方式；但 LabelImg 的安裝通常需要透過 Python 套件管理工具或其他適用的安裝方式完成。


### 4.2 標註水果位置及類別

開啟 LabelImg 後，先選擇存放水果圖片的資料夾，再逐張開啟圖片。使用滑鼠框選圖片中的水果，建立物件的邊界框，並輸入對應的類別名稱，例如 Apple。

影像標註的目的是讓模型在訓練時能夠學習水果所在的位置及類別，因此應盡量確保框選範圍正確，並統一使用相同的類別名稱。

圖 4-1/4-2    LabelImg 安裝或啟動畫面,水果邊界框標註畫面

### 4.3 儲存 XML 標註檔案

完成標註後，將標註資訊儲存為 XML 格式。每張圖片都應有相對應的標註資料，並確認圖片檔案與 XML 檔案的名稱及存放位置正確。

XML 檔案包含物件類別及邊界框等資訊，可作為後續整理標註資料及轉換資料格式的依據。

## 五、準備訓練資料及測試資料

### 5.1 分類訓練資料與測試資料

完成影像標註後，將資料分成訓練資料與測試資料。訓練資料用於讓模型學習水果的特徵，測試資料則用於檢查模型對未參與訓練的圖片之辨識表現。

本專案使用 `images/train` 存放訓練圖片，並使用 `images/test` 存放測試圖片。分類完成後，應確認圖片與對應的標註資訊皆已正確整理。

### 5.2 整理標註資訊

本專案的資料轉換流程會使用 `train_labels.csv` 及 `test_labels.csv` 等標註資料檔案。應確認這些檔案內的圖片名稱、類別名稱及物件位置等資訊與實際圖片相符。

若前一步使用 LabelImg 產生 XML 檔案，則應依照專案原本的程式流程，將 XML 標註資料整理或轉換成程式需要的 CSV 格式。不能直接假設 XML 與 CSV 可以互相取代。

## 六、使用 generate_tfrecord.py 轉換資料格式

### 6.1 認識 generate_tfrecord.py

`generate_tfrecord.py` 是本專案資料準備流程中的重要程式，其用途是將圖片及對應的標註資訊轉換成 TensorFlow 模型訓練所需的 TFRecord 格式。

完成資料轉換後，模型訓練程式即可讀取轉換後的資料，進行後續訓練。

### 6.2 產生訓練資料 train.record

執行 `generate_tfrecord.py` 時，指定訓練圖片、訓練標註資料及輸出檔案位置，產生 `data/train.record`。

轉換完成後，確認輸出檔案已成功建立，並檢查執行過程是否出現錯誤訊息。


### 6.3 產生測試資料 test.record

完成訓練資料轉換後，以相同的資料轉換流程處理測試資料，產生 `data/test.record`。

完成後，應確認 `train.record` 與 `test.record` 均已建立，並確認程式設定的路徑與實際資料夾一致。


## 七、確認模型訓練前的設定

### 7.1 確認模型設定檔

開始訓練前，應確認模型設定檔、訓練資料路徑、測試資料路徑及類別數量等設定正確。

若本專案使用預先訓練的物件辨識模型，還應確認模型檔案及相關設定與實際使用的 TensorFlow Object Detection API 版本相容。

### 7.2 確認標籤資料

模型訓練前，必須確認標籤資料中的類別名稱與實際標註內容一致，並確認類別數量設定正確，避免模型因標籤資料不一致而無法正常訓練。

## 八、開始訓練模型(使用SSD_MOBILENET_V2模型訓練)

### 8.1 設定訓練步數

完成圖片蒐集、影像標註及訓練資料準備後，即可開始訓練物件辨識模型。

本專案預計先將訓練步數設定為 **200 步**，用來測試模型是否能正常執行訓練流程。訓練步數代表模型更新參數的次數，實際辨識效果仍須透過後續測試確認。

### 8.2 修改模型儲存間隔

模型原本預設每 1,000 步儲存一次檢查點（Checkpoint）。由於本次訓練設定為 200 步，因此需要將模型儲存間隔調整為每 **100 步**儲存一次。

如此一來，在訓練過程中便有機會產生第 100 步及第 200 步的檢查點，方便確認模型是否有成功儲存。

### 8.3 執行模型訓練

完成設定後，執行模型訓練程式，並觀察終端機或執行環境中的訓練訊息，確認訓練是否正常進行。

訓練過程中若出現錯誤，應先檢查資料路徑、模型設定檔、套件版本及訓練資料格式，再重新執行程式。

 ![03](https://github.com/11325034/AI/blob/main/8-1.png)

 圖 8-1　模型訓練執行畫面

### 8.4 確認模型是否成功儲存

訓練完成後，前往指定的模型輸出資料夾，確認是否已產生模型檢查點及相關索引檔案。

確認模型檔案確實存在，且訓練流程正常完成後，才能進入下一步驟進行模型匯出。若沒有成功產生檢查點，應先檢查訓練輸出路徑及儲存設定。


## 九、匯出訓練完成的模型

### 9.1 確認匯出條件

確認模型訓練完成，且已成功儲存相關檢查點後，即可進行模型匯出。

執行匯出前，應確認模型設定檔、訓練產生的檢查點及類別標籤資訊均位於正確位置，並確認匯出程式與目前使用的 TensorFlow Object Detection API 版本相容。

### 9.2 執行模型匯出

依照本專案使用的模型架構及 API 版本，執行相對應的匯出程式，將訓練產生的檢查點轉換為後續辨識程式可使用的模型格式。

匯出過程中，應注意輸入檔案路徑與輸出資料夾設定，並觀察執行訊息，確認匯出程序是否正常完成。


### 9.3 確認匯出結果

模型匯出完成後，檢查指定輸出資料夾，確認是否產生預期的模型檔案。

確認檔案存在後，即可將匯出的模型作為後續水果影像辨識測試的基礎。若模型無法正常載入，應檢查匯出格式、模型版本及相關路徑是否正確。

## 十、錯誤排除與注意事項

### 10.1 找不到 object_detection 模組

若執行程式時出現 `ModuleNotFoundError: No module named 'object_detection'`，代表目前的 Python 執行環境無法找到 `object_detection` 模組。

此時應確認 TensorFlow Models 相關原始碼是否已準備完成，並依照所使用版本的安裝方式設定 Python 模組搜尋路徑或完成安裝。也應確認執行程式所使用的 Python 環境與安裝套件的環境相同。

### 10.2 訓練資料無法讀取

若程式無法讀取圖片或標註資料，應檢查資料夾路徑、檔案名稱、標註格式及資料夾權限是否正確。

此外，應確認 `train.record` 與 `test.record` 已成功產生，且模型設定檔指向正確的檔案位置。

### 10.3 訓練完成卻沒有模型檔案

若訓練結束後沒有找到預期的模型檔案，應確認檢查點儲存間隔、訓練步數、輸出資料夾及程式執行狀態。

本專案設定為訓練 200 步、每 100 步儲存一次，因此應特別確認模型輸出目錄是否正確，以及訓練過程是否實際執行到儲存檢查點的步數。
